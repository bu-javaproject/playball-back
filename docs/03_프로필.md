# 03. 프로필 조회·수정 흐름

---

## 전체 흐름 요약

```
내 프로필 조회    → GET  /api/members/me
다른 회원 조회   → GET  /api/members/{memberId}
프로필 수정      → PATCH /api/members/me
위치 업데이트    → PATCH /api/members/me/location
회원 탈퇴        → DELETE /api/members/withdraw
```

---

## 1. 내 프로필 조회

### API
```
GET /api/members/me
Authorization: Bearer {accessToken} 필요
```

### 서버 처리
```
1. JWT에서 memberId 추출
2. MemberRepository.findById(memberId) 조회
3. ProfileResponse 변환 후 반환
```

### 응답
```json
{
  "success": true,
  "message": "프로필 조회 성공",
  "data": {
    "memberId": 1,
    "nickname": "홍길동",
    "profileImage": "https://k.kakaocdn.net/...",
    "gender": "M",
    "age": 22,
    "address": "서울시 노원구 신부동",
    "skillLevel": "INTERMEDIATE",
    "preferredPosition": "ST",
    "favoriteSports": ["SOCCER", "BASKETBALL"]
  }
}
```

> **민감 정보는 응답에서 제외됩니다:**  
> `kakaoId`, `email`, `name`, `phone`, `role`, `signupCompleted`

## 2. 다른 회원 프로필 조회

### API
```
GET /api/members/{memberId}
Authorization: Bearer {accessToken} 필요
```

### 서버 처리
```
1. PathVariable로 memberId 수신
2. MemberRepository.findById(memberId) 조회
   → 없으면 404 (USER_NOT_FOUND)
3. ProfileResponse 변환 후 반환 (민감 정보 동일하게 제외)
```

---

## 3. 프로필 수정

### API
```
PATCH /api/members/me
Authorization: Bearer {accessToken} 필요
```

### 요청
```json
{
  "nickname": "새닉네임",
  "address": "서울시 강남구",
  "latitude": 37.5665,
  "longitude": 126.9780,
  "favoriteSports": ["SOCCER", "BADMINTON"]
}
```

### 부분 업데이트 규칙
| 필드 | null 전달 시 | 빈 값("") 전달 시 |
|------|------------|----------------|
| `nickname` | 변경 안 함 | 400 에러 (2자 미만) |
| `address` | 변경 안 함 | 빈 문자열로 저장 |
| `latitude`, `longitude` | 변경 안 함 | - |
| `favoriteSports` | 변경 안 함 | 빈 배열(`[]`)이면 전체 삭제 |

### 서버 내부 처리 순서

```
1. JWT에서 memberId 추출 → DB에서 Member 조회

2. 닉네임 변경 요청이 있을 때만 중복 확인
   조건: nickname != null && nickname != 현재닉네임 && DB에 이미 존재
   → 409 (NICKNAME_ALREADY_EXISTS)

3. member.updateProfile() 호출
   → nickname: null이 아니고 빈 문자열이 아닐 때만 업데이트
   → address, latitude, longitude: null이 아닐 때만 업데이트

4. favoriteSports 변경 요청이 있을 때
   → 기존 목록 clear() 후 새 목록 addAll()

5. 변경된 ProfileResponse 반환
```

### member.updateProfile() 내부 로직
```java
// Member.java
public void updateProfile(String nickname, String address, Double latitude, Double longitude) {
    if (nickname != null && !nickname.isBlank()) this.nickname = nickname;
    if (address != null) this.address = address;
    if (latitude != null) this.latitude = latitude;
    if (longitude != null) this.longitude = longitude;
}
// favoriteSports는 Service에서 직접 처리
```

### 에러
| 상황 | HTTP | 에러코드 |
|------|------|---------|
| 닉네임 중복 | 409 | `NICKNAME_ALREADY_EXISTS` |
| nickname이 빈 문자열이거나 1자 | 400 | Bean Validation |

## 4. 위치 업데이트

### API
```
PATCH /api/members/me/location
Authorization: Bearer {accessToken} 필요
```

### 요청
```json
{
  "latitude": 37.6394,
  "longitude": 127.0722,
  "address": "서울시 노원구 신부동"
}
```

> `latitude`, `longitude`는 필수입니다 (`@NotNull`).  
> `address`는 선택 (역지오코딩 결과를 프론트에서 채워서 보냄).

### 서버 처리
```
1. memberId 추출 → Member 조회
2. member.updateLocation(latitude, longitude, address) 호출
   → 세 필드 모두 덮어씀 (null 체크 없음)
3. 성공 응답
```

---

## 5. 회원 탈퇴

### API
```
DELETE /api/members/withdraw
Authorization: Bearer {accessToken} 필요
```

### 서버 처리
```
1. memberId 추출 → Member 조회
2. memberRepository.delete(member) 실행 (하드 삭제)
3. 성공 응답
```

> 탈퇴 시 관련 데이터(경기 참가 기록, 칭찬 등)도 CASCADE 설정에 따라 함께 삭제될 수 있습니다.

| 사용처 | 프로필 조회·수정 응답 | 회원가입 완료 응답 |
| memberId | ✅ | ✅ |
| nickname | ✅ | ✅ |
| profileImage | ✅ | ✅ |
| gender, age | ✅ | ✅ |
| address | ✅ | ✅ |
| skillLevel | ✅ | ✅ |
| favoriteSports | ✅ | ✅ |
| kakaoId | ❌ | ✅ |
| email | ❌ | ✅ |
| name, phone | ❌ | ✅ |
| role | ❌ | ✅ |
| signupCompleted | ❌ | ✅ |
| createdAt, updatedAt | ❌ | ✅ |
