# 07. 매칭 성공 후 내 경기 조회 흐름

---

## 전체 흐름 요약

```
참가 완료 화면 → "경기 상세 보기" 버튼
    → 내 경기 목록  GET /api/members/me/matches
    → 경기 클릭     GET /api/matches/{matchId}
    → 세부내역 확인 + 참가자 목록 확인 (같은 API)
```

---

## 1. 내가 참가한 경기 목록 조회

### API
```
GET /api/members/me/matches
Authorization: Bearer {accessToken} 필요
```

### 서버 내부 처리 순서

```
1. JWT에서 memberId 추출

2. DB 조회 (findMyMatches 쿼리)
   → 조건: memberId = 내 ID, status = APPROVED, match.status != DELETED
   → 경기일 역순 정렬 (최근 경기가 위로)

3. 각 MatchParticipant → match 꺼내서 MatchResponse 변환

4. 리스트 반환
```

### 조회 쿼리
```java
// JPQL (MatchParticipantRepository)
SELECT mp FROM MatchParticipant mp
JOIN FETCH mp.match m
WHERE mp.member.memberId = :memberId
  AND mp.status = :status              -- APPROVED만
  AND m.status != MatchStatus.DELETED  -- 삭제된 경기 제외
ORDER BY m.matchDate DESC
```

> `JOIN FETCH`를 사용해 N+1 문제를 방지합니다.  
> (참가자 조회 시 경기 정보를 한 번의 쿼리로 함께 가져옴)

## 2. 경기 세부내역 + 참가자 목록 조회

### API
```
GET /api/matches/{matchId}
인증 불필요 (비로그인도 가능)
```

> 이 API 하나로 **경기 세부내역**과 **참가자 목록** 두 화면을 모두 처리합니다.

### 서버 내부 처리 순서

```
1. matchId로 경기 조회
   → 없으면 404 (MATCH_NOT_FOUND)
   → status == DELETED이면 404 (MATCH_DELETED)

2. APPROVED 상태 참가자 목록 조회
   SELECT * FROM match_participant
   WHERE match_id = ? AND status = 'APPROVED'

3. MatchDetailResponse 구성
   → match 정보 + joinedMembers 목록

4. 응답 반환
```

---

## 내 경기 vs 전체 경기 목록 차이

| 구분 | 내 경기 | 전체 경기 |
|------|---------|---------|
| API | `GET /api/members/me/matches` | `GET /api/matches` |
| 조건 | 내가 APPROVED 참가한 것 | 전체 (DELETED 제외) |
| 정렬 | 경기일 역순 | 등록일 역순 또는 거리순 |
| DELETED 포함 | ❌ | ❌ |
| CLOSED 포함 | ✅ | ✅ |
| 인증 | 필요 | 불필요 |

---

## MemberInfo에 포함되는 정보

참가자 목록(`joinedMembers`)의 각 항목에는 아래 정보가 포함됩니다.

```
memberId         (프로필 페이지 이동에 사용)
nickname         (표시 이름)
profileImage     (프로필 이미지 URL, null 가능)
gender           (성별)
age              (나이)
skillLevel       (실력)
preferredPosition (선호 포지션)
```

> 민감 정보(kakaoId, email, phone 등)는 포함되지 않습니다.
