# 04. 지역 매칭 — 참가자 흐름

---

## 전체 흐름 요약

```
현재 위치 업데이트  → PATCH /api/members/me/location
주변 경기 목록 조회  → GET  /api/matches?latitude=&longitude=&radius=&sportType=
경기 상세 조회       → GET  /api/matches/{matchId}
경기 참가           → POST /api/matches/{matchId}/join
경기 참가 취소      → DELETE /api/matches/{matchId}/join
```

---

## 1. 주변 경기 목록 조회 (위치 기반)

### API
```
GET /api/matches?latitude=37.6394&longitude=127.0722&radius=5.0&sportType=SOCCER
인증 불필요 (비로그인도 가능)
```

### 파라미터
| 파라미터 | 필수 | 기본값 | 설명 |
|---------|------|--------|------|
| `latitude` | 위치 기반 시 필수 | - | 검색 기준 위도 |
| `longitude` | 위치 기반 시 필수 | - | 검색 기준 경도 |
| `radius` | ❌ | 5.0 | 검색 반경 (km) |
| `sportType` | ❌ | 전체 | SOCCER / BASKETBALL / RUNNING / BADMINTON |
| `page`, `size` | ❌ | 0, 10 | 위치 미제공 시 일반 페이지네이션 |

### 동작 모드
```
latitude + longitude 제공 → 위치 기반 검색 (거리순 정렬)
미제공                    → 전체 목록 페이지네이션 (DELETED 제외)
```

### 위치 기반 쿼리 (Haversine 공식)
```sql
SELECT id, title, sport_type, match_date, location_name,
       latitude, longitude, max_players, current_players, status,
       (6371 * ACOS(
           COS(RADIANS(:latitude)) * COS(RADIANS(latitude))
           * COS(RADIANS(longitude) - RADIANS(:longitude))
           + SIN(RADIANS(:latitude)) * SIN(RADIANS(latitude))
       )) AS distance
FROM matches
WHERE status = 'OPEN'
  AND (:sportType IS NULL OR sport_type = :sportType)
HAVING distance <= :radius
ORDER BY distance
```

> - `status = 'OPEN'`인 경기만 반환 (CLOSED, DELETED 제외)
> - 거리 단위는 **km**
> - 6371은 지구 반지름(km)

## 3. 경기 참가

### API
```
POST /api/matches/{matchId}/join
Authorization: Bearer {accessToken} 필요
```

### 서버 내부 처리 순서 (중요!)

```
1. matchId로 경기 조회
   → 없으면 404 (MATCH_NOT_FOUND)

2. 경기 상태 확인
   → status == DELETED이면 404 (MATCH_DELETED)

3. 인원 확인
   → currentPlayers >= maxPlayers이면 409 (MATCH_FULL)

4. 중복 참가 확인
   → PENDING 또는 APPROVED 상태로 이미 참가 중이면 409 (ALREADY_JOINED)

5. memberId로 회원 조회
   → 없으면 404 (USER_NOT_FOUND)

6. MatchParticipant 생성 (status: APPROVED)

7. match.currentPlayers + 1
   → 인원이 maxPlayers에 달하면 status를 OPEN → CLOSED로 자동 변경

8. 응답 반환
```

### 낙관적 락 (동시성 처리)

Match 엔티티에 `@Version` 필드가 있어 동시에 여러 명이 참가할 때 충돌을 방지합니다.

```
A, B 동시에 마지막 자리에 참가 시도
  → A 성공, Match version 1 → 2
  → B가 DB 업데이트 시 version이 이미 2로 바뀜
  → OptimisticLockingFailureException 발생
  → GlobalExceptionHandler가 409 (MATCH_JOIN_CONFLICT)로 변환
```

### 응답
```json
{
  "success": true,
  "message": "경기 참가 성공",
  "data": {
    "matchId": 1,
    "currentPlayers": 4,
    "maxPlayers": 10,
    "status": "OPEN"
  }
}
```

### 에러
| 상황 | HTTP | 에러코드 |
|------|------|---------|
| 경기 없음 | 404 | `MATCH_NOT_FOUND` |
| 삭제된 경기 | 404 | `MATCH_DELETED` |
| 인원 초과 | 409 | `MATCH_FULL` |
| 이미 참가 중 | 409 | `ALREADY_JOINED` |
| 동시 참가 충돌 | 409 | `MATCH_JOIN_CONFLICT` |

## 4. 경기 참가 취소

### API
```
DELETE /api/matches/{matchId}/join
Authorization: Bearer {accessToken} 필요
```

### 서버 내부 처리 순서

```
1. matchId로 경기 조회
   → 없으면 404 (MATCH_NOT_FOUND)

2. 경기 상태 확인
   → status == DELETED이면 404 (MATCH_DELETED)

3. 참가 기록 조회
   → matchId + memberId로 조회
   → APPROVED 상태 기록이 없으면 400 (NOT_JOINED)
     (이미 취소했거나, 처음부터 참가하지 않은 경우)

4. participant.status = CANCELLED 로 변경

5. match.currentPlayers - 1
   → currentPlayers < maxPlayers이면 status CLOSED → OPEN으로 복구

6. 응답 반환
```

### 응답
```json
{
  "success": true,
  "message": "경기 참가 취소 성공",
  "data": {
    "matchId": 1,
    "currentPlayers": 3,
    "maxPlayers": 10,
    "status": "OPEN"
  }
}
```

### 에러
| 상황 | HTTP | 에러코드 |
|------|------|---------|
| 경기 없음 | 404 | `MATCH_NOT_FOUND` |
| 삭제된 경기 | 404 | `MATCH_DELETED` |
| 참가하지 않은 경기 (또는 이미 취소됨) | 400 | `NOT_JOINED` |

## 참가자 상태 흐름

```
참가 신청 → APPROVED (즉시 승인)
참가 취소 → CANCELLED
```

> 현재 구현에서는 PENDING 단계 없이 즉시 APPROVED 처리됩니다.  
> (주최자 승인 없이 선착순 자동 참가)

### ParticipantStatus 값
| 값 | 설명 |
|----|------|
| `PENDING` | 대기 중 (현재 미사용) |
| `APPROVED` | 참가 확정 |
| `REJECTED` | 거절됨 (현재 미사용) |
| `CANCELLED` | 본인 취소 |
