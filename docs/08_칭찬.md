# 08. 경기 후 칭찬 흐름

---

## 전체 흐름 요약

```
경기 종료 후
    → 같이 뛴 사람 선택 + 태그 선택
    → POST /api/matches/{matchId}/compliments (Bulk 등록)

칭찬 조회
    → GET /api/members/{memberId}/compliments          (받은 칭찬 목록)
    → GET /api/members/{memberId}/compliments/summary  (태그별 누적 카운트)
    → GET /api/matches/{matchId}/compliments/me        (특정 경기 칭찬 내역)
```

---

## 1. 경기 후 칭찬 Bulk 등록

### API
```
POST /api/matches/{matchId}/compliments
Authorization: Bearer {accessToken} 필요
```

### 요청
```json
{
  "compliments": [
    {
      "rateeId": 5,
      "tags": ["MANNERS", "PUNCTUAL"],
      "comment": "오늘 정말 즐거웠습니다"
    },
    {
      "rateeId": 7,
      "tags": ["SKILL"],
      "comment": null
    }
  ]
}
```

### 칭찬 태그 종류
| 태그 | 설명 |
|------|------|
| `MANNERS` | 매너 좋아요 |
| `SKILL` | 실력 좋아요 |
| `PUNCTUAL` | 시간 약속 잘 지켜요 |
| `PASSIONATE` | 열정적이에요 |
| `MOOD_MAKER` | 분위기 메이커 |

### 서버 내부 처리 순서

```
1. 호출자(rater)가 해당 경기의 APPROVED 참가자인지 확인
   → 아니면 403 (NOT_A_PARTICIPANT)

2. 요청 목록에 중복 rateeId가 있는지 확인
   → 같은 batch에서 동일인 중복 칭찬 → 400 (INVALID_INPUT)

3. 각 칭찬 항목에 대해:
   a. 자기 자신인지 확인
      → rateeId == raterId이면 400 (SELF_COMPLIMENT)

   b. ratee가 해당 경기의 APPROVED 참가자인지 확인
      → 아니면 403 (NOT_A_PARTICIPANT)

   c. 이미 이 경기에서 해당 ratee를 칭찬했는지 확인
      → 이미 칭찬했으면 409 (DUPLICATE_COMPLIMENT)

4. 검증 통과 후 저장
   a. Compliment 저장 (compliment 테이블)
   b. 각 태그 저장 (compliment_tag 테이블)
   c. 태그별 누적 카운트 업데이트 (member_compliment_summary 테이블)

5. 저장된 칭찬 수 반환
```

> **트랜잭션 처리:** 1명이라도 검증 실패하면 전체 롤백됩니다.  
> 즉, 2명에게 칭찬하려다 1명 실패 시 나머지 1명도 저장되지 않습니다.

### 응답
```json
{
  "success": true,
  "message": "2명에게 칭찬을 보냈습니다",
  "data": { "created": 2 }
}
```

### 에러
| 상황 | HTTP | 에러코드 |
|------|------|---------|
| 호출자가 경기 참가자 아님 | 403 | `NOT_A_PARTICIPANT` |
| ratee가 경기 참가자 아님 | 403 | `NOT_A_PARTICIPANT` |
| 자기 자신 칭찬 | 400 | `SELF_COMPLIMENT` |
| 같은 batch에서 rateeId 중복 | 400 | `INVALID_INPUT` |
| 이미 해당 경기에서 칭찬함 | 409 | `DUPLICATE_COMPLIMENT` |

## 2. 받은 칭찬 목록 조회 (Cursor 페이지네이션)

### API
```
GET /api/members/{memberId}/compliments?cursor=88&size=10
```

### 파라미터
| 파라미터 | 필수 | 설명 |
|---------|------|------|
| `memberId` | ✅ (path) | 조회할 회원 ID |
| `cursor` | ❌ | 마지막으로 받은 complimentId (첫 요청 시 생략) |
| `size` | ❌ | 한 번에 가져올 개수 (기본값: 10) |

### Cursor 페이지네이션 동작 방식
```
첫 요청: cursor 없이 호출 → 최신 10개 반환 + nextCursor 포함
다음 요청: cursor=87로 호출 → complimentId < 87인 것 중 최신 10개
nextCursor가 null이면 더 이상 데이터 없음 (마지막 페이지)
```

### 서버 처리
```
1. cursor가 없으면 전체에서, 있으면 cursor 이전 데이터를 complimentId 역순으로 조회
2. 칭찬 ID 목록으로 태그 일괄 조회 (N+1 방지)
3. 칭찬별로 태그 매핑
4. nextCursor 계산: 조회 결과가 size보다 적으면 null, 아니면 마지막 항목의 complimentId
```

### 응답
```json
{
  "success": true,
  "message": "칭찬 목록 조회 성공",
  "data": {
    "items": [
      {
        "complimentId": 88,
        "matchId": 12,
        "raterId": 3,
        "rateeId": 1,
        "tags": ["MANNERS", "PUNCTUAL"],
        "comment": "오늘 정말 즐거웠습니다",
        "createdAt": "2026-05-17T19:30:00"
      },
      {
        "complimentId": 87,
        "matchId": 10,
        "raterId": 4,
        "rateeId": 1,
        "tags": ["SKILL"],
        "comment": null,
        "createdAt": "2026-05-15T20:15:00"
      }
    ],
    "nextCursor": 87
  }
}
```

## 3. 칭찬 누적 카운트 조회 (프로필용)

### API
```
GET /api/members/{memberId}/compliments/summary
```

### 서버 처리
```
1. member_compliment_summary 테이블에서 memberId로 조회
   → 태그별 누적 카운트가 이미 집계된 상태로 저장돼 있음
2. 결과를 태그별 Map으로 변환 (없는 태그는 0으로 채움)
3. 전체 합계(totalCount) 계산
```

> **member_compliment_summary 테이블을 별도로 사용하는 이유:**  
> 매번 칭찬 테이블 전체를 GROUP BY로 집계하면 느립니다.  
> 칭찬 등록 시 summary 테이블의 카운트를 즉시 증가시켜 빠른 조회를 지원합니다.

### 응답
```json
{
  "success": true,
  "message": "칭찬 통계 조회 성공",
  "data": {
    "memberId": 1,
    "totalCount": 35,
    "tagCounts": {
      "MANNERS": 12,
      "SKILL": 8,
      "PUNCTUAL": 7,
      "PASSIONATE": 5,
      "MOOD_MAKER": 3
    }
  }
}
```

## 4. 특정 경기에서 내가 한/받은 칭찬 조회

### API
```
GET /api/matches/{matchId}/compliments/me
Authorization: Bearer {accessToken} 필요
```

### 서버 처리
```
1. memberId를 rater로 해서 해당 경기에서 보낸 칭찬 조회 (given)
2. memberId를 ratee로 해서 해당 경기에서 받은 칭찬 조회 (received)
3. 두 목록의 complimentId를 합쳐서 태그 일괄 조회
4. 각 칭찬에 태그 매핑 후 반환
```

### 응답
```json
{
  "success": true,
  "message": "경기 칭찬 조회 성공",
  "data": {
    "given": [
      {
        "complimentId": 88,
        "matchId": 12,
        "raterId": 1,
        "rateeId": 5,
        "tags": ["MANNERS"],
        "comment": "재밌었어요",
        "createdAt": "2026-05-17T19:30:00"
      }
    ],
    "received": [
      {
        "complimentId": 90,
        "matchId": 12,
        "raterId": 4,
        "rateeId": 1,
        "tags": ["SKILL", "PASSIONATE"],
        "comment": null,
        "createdAt": "2026-05-17T19:35:00"
      }
    ]
  }
}
```

## DB 구조 참고

### compliment 테이블
```
compliment_id  BIGINT (PK)
match_id       BIGINT (어느 경기에서)
rater_id       BIGINT (칭찬한 사람)
ratee_id       BIGINT (칭찬받은 사람)
comment        TEXT (선택)
created_at     DATETIME
```

### compliment_tag 테이블
```
id             BIGINT (PK)
compliment_id  BIGINT (FK → compliment)
tag            VARCHAR (MANNERS / SKILL / PUNCTUAL / PASSIONATE / MOOD_MAKER)
```

### member_compliment_summary 테이블 (집계 캐시)
```
member_id  BIGINT (PK 구성)
tag        VARCHAR (PK 구성)
count      INT (누적 칭찬 수)
```
