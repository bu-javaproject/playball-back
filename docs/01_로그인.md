# 01. 로그인 / 로그아웃 / 토큰 재발급 흐름

---

## 전체 흐름 요약

```
[프론트] 카카오 로그인 버튼 클릭
    → 카카오 인증 페이지 (프론트가 직접 처리)
    → 카카오가 인가코드 발급
    → POST /api/auth/kakao { authorizationCode }
    → 서버에서 카카오 API 호출 → 사용자 정보 획득
    → JWT 발급 후 응답
```

---

## 1. 카카오 로그인

### API
```
POST /api/auth/kakao
인증 불필요 (비로그인 접근 가능)
```

### 요청
```json
{ "authorizationCode": "카카오에서_받은_인가코드" }
```

### 서버 내부 처리 순서

```
1. 카카오 API 호출 (KakaoOAuthService)
   POST https://kauth.kakao.com/oauth/token  → accessToken 발급
   GET  https://kapi.kakao.com/v2/user/me    → 사용자 정보 (kakaoId, email, nickname, profileImage)

2. DB에서 kakaoId로 회원 조회 (MemberRepository)
   ├─ 기존 회원 → 그대로 사용
   └─ 신규 회원 → Member 생성 후 저장 (role: "USER", signupCompleted: false)

3. JWT 발급 (JwtTokenProvider)
   ├─ accessToken  (만료: 30분, payload: memberId + role)
   └─ refreshToken (만료: 7일, 랜덤 UUID)

4. refreshToken을 DB에 저장 (RefreshToken 테이블)
   → 기존 토큰이 있으면 먼저 삭제 후 새로 저장

5. 응답 반환
```

### 응답 — 기존 회원
```json
{
  "success": true,
  "message": "로그인 성공",
  "data": {
    "accessToken": "eyJhbGci...",
    "refreshToken": "abc123...",
    "tokenType": "Bearer",
    "isNewUser": false,
    "member": { "memberId": 1, "nickname": "홍길동", "role": "USER" }
  }
}
```

### 응답 — 신규 회원
```json
{
  "success": true,
  "message": "추가 정보 입력이 필요합니다",
  "data": {
    "accessToken": "eyJhbGci...",
    "refreshToken": "abc123...",
    "tokenType": "Bearer",
    "isNewUser": true,
    "member": { "memberId": 2, "nickname": null, "role": "USER" }
  }
}
```

> **프론트 처리:** `isNewUser: true`이면 accessToken을 저장한 뒤 회원가입 추가정보 입력 화면으로 이동

### 에러
| 상황 | HTTP | 메시지 |
|------|------|--------|
| 카카오 API 실패 (인가코드 만료 등) | 401 | 카카오 인증에 실패했습니다. |

## 2. 토큰 재발급

### API
```
POST /api/auth/refresh
인증 불필요
```

### 요청
```json
{ "refreshToken": "저장해둔_리프레시_토큰" }
```

### 서버 내부 처리 순서

```
1. refreshToken으로 DB 조회
   → 없으면 401 (INVALID_TOKEN)

2. 만료 여부 확인
   → 만료됐으면 DB에서 삭제 후 401 (EXPIRED_TOKEN)

3. memberId로 회원 조회
   → 없으면 404 (USER_NOT_FOUND)

4. 새 accessToken + refreshToken 발급
   → 기존 refreshToken 삭제 후 새 토큰 저장 (Rotation 방식)

5. 응답 반환
```

> **Rotation 방식:** 재발급할 때마다 refreshToken도 새것으로 교체합니다.  
> 탈취된 토큰으로 한 번 재발급이 일어나면 원래 토큰은 무효화됩니다.

### 에러
| 상황 | HTTP | 메시지 |
|------|------|--------|
| DB에 없는 refreshToken | 401 | 유효하지 않은 토큰입니다. |
| 만료된 refreshToken | 401 | 만료된 토큰입니다. |

---

## 3. 로그아웃

### API
```
POST /api/auth/logout
Authorization: Bearer {accessToken} 필요
```

### 서버 내부 처리

```
1. JWT에서 memberId 추출
2. DB에서 해당 memberId의 refreshToken 삭제
3. 성공 응답
```

> 서버는 accessToken을 블랙리스트로 관리하지 않습니다.  
> 프론트에서 저장된 토큰을 직접 삭제해야 합니다.

## 4. JWT 인증 필터 동작 방식

모든 API 요청은 `JwtAuthenticationFilter`를 거칩니다.

```
요청 수신
  → Authorization 헤더 확인
  ├─ 없음 → 비로그인 허용 경로면 통과, 아니면 401
  └─ 있음 → JWT 파싱 및 검증
           ├─ 유효 → SecurityContext에 memberId 저장 → 컨트롤러 진입
           └─ 만료/변조 → 401 반환
```

**비로그인 허용 경로 (SecurityConfig):**
- `POST /api/auth/kakao`, `POST /api/auth/refresh`
- `GET /api/members/check-nickname`
- `GET /api/matches/**` (경기 목록·상세 조회)
- `/swagger-ui/**`, `/v3/api-docs/**`
- `/ws/**` (WebSocket)

**`@CurrentMemberId`란?**  
컨트롤러 파라미터에서 `@CurrentMemberId Long memberId`로 선언하면 JWT에서 추출한 memberId가 자동으로 주입됩니다. (`CurrentMemberIdArgumentResolver` 처리)
