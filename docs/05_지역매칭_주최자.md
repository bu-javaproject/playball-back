# 05. 지역 매칭 — 주최자 흐름

---

## 전체 흐름 요약

```
경기 생성  → POST  /api/matches
경기 수정  → PATCH /api/matches/{matchId}
경기 삭제  → DELETE /api/matches/{matchId}
```

---

## 1. 경기 생성

### API
```
POST /api/matches
Authorization: Bearer {accessToken} 필요
```

### 요청
```json
{
  "title": "백석대 컴공 축구 내기",
  "sportType": "SOCCER",
  "matchDate": "2026-05-30T19:00:00",
  "locationName": "서울 목동운동장",
  "latitude": 37.5283,
  "longitude": 126.8755,
  "address": "서울시 양천구 목동",
  "maxPlayers": 10,
  "gender": "M",
  "ageRange": 20,
  "skillLevel": "INTERMEDIATE",
  "entryFee": 0,
  "description": "백석대 근처 축구하실 분 구합니다!"
}
```

### 필수/선택 필드
| 필드 | 필수 | 검증 | 비고 |
|------|------|------|------|
| `title` | ✅ | `@NotBlank` | - |
| `sportType` | ✅ | `@NotBlank` | SOCCER / BASKETBALL / RUNNING / BADMINTON |
| `matchDate` | ✅ | `@NotNull`, `@FutureOrPresent` | 현재 시각 이후만 가능 |
| `latitude` | ✅ | `@NotNull` | - |
| `longitude` | ✅ | `@NotNull` | - |
| `maxPlayers` | ✅ | `@NotNull`, `@Min(1)` | - |
| `locationName` | ❌ | - | - |
| `address` | ❌ | - | - |
| `gender` | ❌ | - | null이면 무관 |
| `ageRange` | ❌ | - | null이면 무관, 예: 20 = 20대 |
| `skillLevel` | ❌ | - | null이면 무관 |
| `entryFee` | ❌ | `@Min(0)` | null이면 0으로 처리 |
| `description` | ❌ | - | 공지 메시지 |

### 서버 내부 처리 순서

```
1. JWT에서 hostId(memberId) 추출
2. DB에서 회원 조회 (검증 먼저!)
   → 없으면 404 (USER_NOT_FOUND)

3. sportType 문자열 → SportType 열거형 변환
   → 유효하지 않은 값이면 400 (INVALID_INPUT)
   → 예: "CRICKET" → 400 에러

4. Match 엔티티 생성
   → hostId, title, sportType, matchDate, locationName, latitude, longitude,
      address, maxPlayers, gender, ageRange, skillLevel, entryFee, description
   → currentPlayers = 1 (생성자 포함)
   → status = OPEN

5. Match 저장 (matchingRepository.save)

6. 생성자를 첫 번째 참가자로 등록
   → MatchParticipant 저장 (status: APPROVED)

7. MatchCreateResponse 반환
```

> **순서가 중요한 이유:** 회원 조회를 DB 저장보다 먼저 수행합니다.  
> 만약 회원이 없는데 Match를 저장하면 불필요한 DB row가 생깁니다.

### 응답
```json
{
  "success": true,
  "message": "경기 생성 성공",
  "data": {
    "matchId": 1,
    "title": "백석대 컴공 축구 내기",
    "sportType": "SOCCER",
    "matchDate": "2026-05-30T19:00:00",
    "locationName": "서울 목동운동장",
    "latitude": 37.5283,
    "longitude": 126.8755,
    "address": "서울시 양천구 목동",
    "maxPlayers": 10,
    "currentPlayers": 1,
    "gender": "M",
    "ageRange": 20,
    "skillLevel": "INTERMEDIATE",
    "entryFee": 0,
    "description": "백석대 근처 축구하실 분 구합니다!",
    "status": "OPEN"
  }
}
```

### 에러
| 상황 | HTTP | 에러코드 |
|------|------|---------|
| 필수 필드 누락 | 400 | Bean Validation 메시지 |
| 과거 날짜 | 400 | Bean Validation 메시지 |
| 유효하지 않은 sportType | 400 | `INVALID_INPUT` |
| 회원 없음 | 404 | `USER_NOT_FOUND` |

## 2. 경기 수정

### API
```
PATCH /api/matches/{matchId}
Authorization: Bearer {accessToken} 필요 (주최자만 가능)
```

### 요청 (변경할 필드만 포함)
```json
{
  "title": "백석대 컴공 축구 내기 (인원 추가)",
  "maxPlayers": 12,
  "description": "인원 늘렸습니다!",
  "entryFee": 0
}
```

### 수정 가능 필드
| 필드 | 검증 | 비고 |
|------|------|------|
| `title` | - | - |
| `matchDate` | `@FutureOrPresent` | 과거 날짜 불가 |
| `maxPlayers` | `@Min(1)` | **현재 참가 인원 이상이어야 함** |
| `entryFee` | `@Min(0)` | - |
| `description` | - | - |

> 장소(`locationName`, `latitude`, `longitude`), 종목(`sportType`), 성별/나이 제한은 수정 불가합니다.

### 서버 내부 처리 순서

```
1. matchId로 경기 조회
   → 없으면 404 (MATCH_NOT_FOUND)
   → status == DELETED이면 404 (MATCH_DELETED)

2. 주최자 확인
   → match.hostId != 요청자 memberId이면 403 (FORBIDDEN)

3. maxPlayers 검증
   → request.maxPlayers != null && request.maxPlayers < match.currentPlayers
   → 400 (INVALID_INPUT)

4. match.update() 호출
   → null이 아닌 필드만 덮어씀

5. MatchUpdateResponse 반환
```

### match.update() 내부 로직
```java
// Match.java
public void update(String title, LocalDateTime matchDate, Integer maxPlayers,
                   Integer entryFee, String description) {
    if (title != null) this.title = title;
    if (matchDate != null) this.matchDate = matchDate;
    if (maxPlayers != null) this.maxPlayers = maxPlayers;
    if (entryFee != null) this.entryFee = entryFee;
    if (description != null) this.description = description;
}
```

### 응답
```json
{
  "success": true,
  "message": "경기 수정 성공",
  "data": {
    "matchId": 1,
    "title": "백석대 컴공 축구 내기 (인원 추가)",
    "matchDate": "2026-05-30T19:00:00",
    "maxPlayers": 12,
    "currentPlayers": 3,
    "description": "인원 늘렸습니다!",
    "entryFee": 0,
    "status": "OPEN",
    "updatedAt": "2026-05-17T16:00:00"
  }
}
```

### 에러
| 상황 | HTTP | 에러코드 |
|------|------|---------|
| 경기 없음 또는 삭제됨 | 404 | `MATCH_NOT_FOUND` / `MATCH_DELETED` |
| 주최자가 아님 | 403 | `FORBIDDEN` |
| maxPlayers < currentPlayers | 400 | `INVALID_INPUT` |
| 과거 날짜로 변경 시도 | 400 | Bean Validation |

## 3. 경기 삭제

### API
```
DELETE /api/matches/{matchId}
Authorization: Bearer {accessToken} 필요 (주최자만 가능)
```

### 서버 내부 처리 순서

```
1. matchId로 경기 조회
   → 없으면 404 (MATCH_NOT_FOUND)
   → status == DELETED이면 404 (MATCH_DELETED)

2. 주최자 확인
   → match.hostId != 요청자 memberId이면 403 (FORBIDDEN)

3. match.markDeleted() 호출
   → match.status = DELETED (소프트 삭제)
   → DB에서 실제로 삭제하지 않음!

4. 성공 응답
```

### 소프트 삭제란?
```
DB에서 행(row)을 실제로 지우지 않고, status를 DELETED로 변경합니다.
삭제 후:
  → GET /api/matches 목록에서 제외됨
  → GET /api/matches/{id} 상세 조회 시 404 반환
  → 참가 이력 등 관련 데이터는 DB에 보존됨
```

### 에러
| 상황 | HTTP | 에러코드 |
|------|------|---------|
| 경기 없음 또는 이미 삭제됨 | 404 | `MATCH_NOT_FOUND` / `MATCH_DELETED` |
| 주최자가 아님 | 403 | `FORBIDDEN` |

## Match 상태 전이

```
생성 시작
    ↓
  OPEN  ──── 참가자가 꽉 참 ────→ CLOSED
    ↑                                  │
    └──── 참가자가 취소 ────────────────┘
    │
    └──── 주최자가 삭제 ────→ DELETED (최종, 복구 불가)
```

### MatchStatus 값
| 값 | 설명 |
|----|------|
| `OPEN` | 참가 가능 |
| `CLOSED` | 인원 마감 (참가 불가) |
| `DELETED` | 삭제됨 (조회/참가 불가) |

## DB 구조 참고

### matches 테이블 (핵심 필드)
```
id               BIGINT (PK)
version          BIGINT (낙관적 락, @Version)
host_id          BIGINT (주최자 memberId)
title            VARCHAR
sport_type       VARCHAR (SOCCER / BASKETBALL / RUNNING / BADMINTON)
match_date       DATETIME
location_name    VARCHAR
latitude         DOUBLE
longitude        DOUBLE
address          VARCHAR
max_players      INT
current_players  INT
gender           VARCHAR (null = 무관)
age_range        INT    (null = 무관)
skill_level      VARCHAR
entry_fee        INT    (0 = 무료)
description      TEXT
status           VARCHAR (OPEN / CLOSED / DELETED)
created_at       DATETIME
updated_at       DATETIME
```

### match_participant 테이블
```
participant_id  BIGINT (PK)
match_id        BIGINT (FK → matches.id)
member_id       BIGINT (FK → member.member_id)
status          VARCHAR (PENDING / APPROVED / REJECTED / CANCELLED)
applied_at      DATETIME
updated_at      DATETIME
UNIQUE (match_id, member_id)
```
