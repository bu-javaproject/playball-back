# 06. 랜덤 매칭 흐름

---

## 전체 흐름 요약

```
조건 입력 (위치, 날짜, 종목, 성별, 나이, 실력, 참가비)
    → POST /api/matches/random
    → 조건에 맞는 경기 1개를 랜덤으로 추천
    → 마음에 들면 POST /api/matches/{matchId}/join 으로 참가
```

---

## 랜덤 매칭 요청

### API
```
POST /api/matches/random
Authorization: Bearer {accessToken} 필요
```

### 요청
```json
{
  "latitude": 37.6394,
  "longitude": 127.0722,
  "radius": 5.0,
  "sportType": "SOCCER",
  "date": "2026-05-30",
  "maxFee": 10000,
  "skillLevel": "INTERMEDIATE",
  "gender": "M",
  "ageRange": 20
}
```

### 필수/선택 필드
| 필드 | 필수 | 설명 |
|------|------|------|
| `latitude` | ✅ | 검색 기준 위도 |
| `longitude` | ✅ | 검색 기준 경도 |
| `sportType` | ✅ | 종목 (SOCCER / BASKETBALL / RUNNING / BADMINTON) |
| `radius` | ❌ | 검색 반경 km (기본값 없음, 필드 없으면 제한 없음) |
| `date` | ❌ | 경기 날짜 (yyyy-MM-dd) |
| `maxFee` | ❌ | 최대 참가비 |
| `skillLevel` | ❌ | BEGINNER / INTERMEDIATE / ADVANCED |
| `gender` | ❌ | M / F (null이면 무관) |
| `ageRange` | ❌ | 연령대 (예: 20 = 20대, null이면 무관) |

---

## 서버 내부 처리 순서

```
1. 요청 파라미터 가공
   → gender: null이 아니면 request.gender.name() 으로 문자열 변환
   → skillLevel: 문자열로 그대로 전달

2. DB 쿼리 실행 (findRandomMatch - 네이티브 쿼리)
   → 조건에 맞는 경기 중 랜덤으로 1개 선택

3. 결과 처리
   → 있으면 → RandomMatchResponse 반환 (200)
   → 없으면 → 404 (MATCH_NOT_FOUND)
```

## 랜덤 매칭 쿼리 상세

```sql
SELECT matchId, title, sportType, matchDate, locationName,
       entryFee, currentPlayers, maxPlayers, distance
FROM (
    SELECT
        id AS matchId, title, sport_type AS sportType,
        match_date AS matchDate, location_name AS locationName,
        entry_fee AS entryFee, current_players AS currentPlayers,
        max_players AS maxPlayers,
        -- Haversine 거리 계산
        (6371 * ACOS(
            COS(RADIANS(:latitude)) * COS(RADIANS(latitude))
            * COS(RADIANS(longitude) - RADIANS(:longitude))
            + SIN(RADIANS(:latitude)) * SIN(RADIANS(latitude))
        )) AS distance
    FROM matches
    WHERE status = 'OPEN'
      AND current_players < max_players          -- 자리 있는 경기만
      AND (:sportType IS NULL OR sport_type = :sportType)
      AND (:date IS NULL OR DATE(match_date) = :date)
      AND (:maxFee IS NULL OR entry_fee <= :maxFee)
      AND (:skillLevel IS NULL OR skill_level = :skillLevel)
      AND (:gender IS NULL OR gender = :gender)
      AND (:ageRange IS NULL OR age_range = :ageRange)
      AND NOT EXISTS (                           -- 이미 참가 중인 경기 제외
          SELECT 1 FROM match_participant mp
          WHERE mp.match_id = matches.id
            AND mp.member_id = :memberId
            AND mp.status IN ('PENDING', 'APPROVED')
      )
) t
WHERE t.distance <= :radius
ORDER BY RAND()                                  -- 랜덤 정렬
LIMIT 1
```

### 핵심 필터 조건 요약
| 조건 | 설명 |
|------|------|
| `status = 'OPEN'` | 참가 가능한 경기만 |
| `current_players < max_players` | 자리가 있는 경기만 |
| `NOT EXISTS (참가 중인 경기)` | 이미 신청했거나 참가 중인 경기 제외 |
| `distance <= :radius` | 반경 내 경기만 |
| `ORDER BY RAND() LIMIT 1` | 조건을 만족하는 경기 중 랜덤 1개 |

## 응답

### 매칭 성공
```json
{
  "success": true,
  "message": "랜덤 매칭 성공",
  "data": {
    "matchId": 3,
    "title": "백석대 축구 내기",
    "sportType": "SOCCER",
    "matchDate": "2026-05-30T19:00:00",
    "locationName": "서울 목동운동장",
    "entryFee": 0,
    "currentPlayers": 7,
    "maxPlayers": 10,
    "distance": 2.3
  }
}
```

### 조건에 맞는 경기 없음
```json
{
  "success": false,
  "message": "존재하지 않는 경기입니다.",
  "data": null
}
```

> 조건에 맞는 경기가 없으면 404를 반환합니다.  
> 프론트는 404 응답 시 "조건에 맞는 경기가 없어요" 화면을 표시하면 됩니다.

## Gender 열거형 처리

`RandomMatchRequest`에서 `gender` 필드는 `String`이 아닌 **별도 열거형**으로 받습니다.

```java
public enum Gender { M, F }
```

서비스에서 쿼리에 전달할 때 `.name()`으로 문자열로 변환합니다.

```java
// MatchService.java
String gender = request.getGender() != null ? request.getGender().name() : null;
```

> null이면 쿼리에서 `:gender IS NULL` 조건이 참이 되어 성별 필터가 적용되지 않습니다.
